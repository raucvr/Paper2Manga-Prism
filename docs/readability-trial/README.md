后续已完成 [38 格带角色阅读版](../character-reading/README.md)。本文保留前一轮文字试验的过程与边界。

这次试验继续解决一个具体问题：读者能看见方法名称，却不知道每一步谁在做、依据什么做、为什么有帮助。

## 工作位置

仅在 `Prism_manga-reader-readable` 的 `codex/prism-readable-content` 分支工作。原始 `Prism_manga-reader` 留给另一个优化进程；不要从此试验脚本写回原目录。

## 本轮发现与修复

真实初稿仍写出“完美答案”“无限循环”，把量化前后假设成具体内存和速度收益，且没有解释老师提供的训练目标。初稿的图解尚未完成，盲读发现的“看不到图解”不能直接算作最终漫画的问题。

一个可复现的代码遗漏是：新手教学提纲 `beginner_plan` 被写稿阶段信任，却没有送入事实校对。本轮让目标、基础知识、开场问题和各步骤的理由都进入校对，并只允许修改当前请求明确列出的字段。问句不能被原文陈述句覆盖；多项删除不会错位；没有 `novice_v1` 标记的旧稿不受影响。

真实校对调用 `deepseek-v4-pro-ga-260813` 用时 88.39 秒，纠正 6 个字段，3 个开场问题均仍为问句。但“缺失/过度使用的词”等用语仍不够精确、也不够浅显。因此，校对完成不等于讲解已经合格。

写稿和修稿提示增加了明确要求：先交代参与者、输入、反馈来源、具体变化和理由；关键解释必须出现在可见文字或实际图标签里，不能只写在隐藏备注或画图要求中。

## 阅读预览工具

`backend/tools/preview_story.py` 将实际分镜中的旁白、对话和项目绘图器生成的图板导出为一个可离线打开的 HTML。它不调用模型，也不生成角色画面。

```sh
.venv/bin/python backend/tools/preview_story.py \
  --script path/to/storyboard.zh-CN.json \
  --before path/to/old-storyboard.json \
  --out path/to/preview.html
```

支持版本切换、图中文字展开、放大图解和键盘操作。图板绘制失败会在页面及报告中明确显示，命令返回非零状态。自动阅读诊断只在文字指纹和语言都匹配时显示，不能替换真实读者验证。

## 这次交付的内容

`storyboard.zh-CN.json` 是 **37 格完整中文教学稿**：Claude Opus 5.5 根据真实初稿和论文重写，GPT-6 Astra 对照论文审阅，主代理继续核对和编辑。它覆盖机制、关键实验和局限；没有绘制角色画面。`before-storyboard.json` 保留原有 21 格脚本的可见字段，供对照，不包含隐藏提纲。

讲解从“想让会解题的模型少占内存”开始，再教权重精度、逐片段生成、前缀、概率和师生角色。它明确：学生文字决定在哪里学习，老师的概率决定学习目标；动态KL按每个候选的偏差混合两种方向。量化使用与训练内存、局部诊断与最终成绩、其他量化基线与完整模型都作了区分。

原有自动流水线在反复校对后，仍长时间停在第36次模型调用；已保存检查点并主动中断。**没有完成该流水线的英文最终稿、中文翻译和端到端验收，不能将本教学稿当成其自动成功结果。** 新的提纲校对代码另做了上述一次真实验证。

Opus 在独立上下文中对可见文字做了两轮盲读；主代理按论文核对后修改，不直接照抄所有建议。最后一轮编辑后没有再次盲读，当前稿的独立阅读检查仍待确认；没有人类理解测试。`astra-review.md` 保存审稿过程及两项阻断关闭结论，`review-resolution.json` 记录最后处理。

### 本地重建与阅读

在这个隔离 worktree 根目录运行：

```sh

```

生成 `output/readability-case/index.html`。HTML 内嵌图解，可直接离线打开，不需要网络、密钥或模型。真实试验预览及交流包另外保存在 `output/readability-trial-20261106-094314/`。

最终预览用本机 Chrome 无头进程验证了 1440、390、320 像素宽度：版本切换、键盘操作、图中文字展开、放大与Escape关闭、焦点返回均通过，没有页面错误或横向溢出。按实际1000×720图板尺寸检查，修订稿没有发生 `_clip` 文字截短。保留图片尺寸避免懒加载时布局跳动。此检查不证明读者已经理解，也不是手机真机验收。

### 下轮优化的起点

1. 先让真实读者回答开场三个问题，记录具体卡住的格，避免只追求AI审阅返回“通过”。
2. 新代码需要一次有时间上限的完整自动生成回归；本轮旧进程在代码修改前已启动，不能算验证了新提示的最终效果。
3. 读者诊断的答案已校验原文引用，但问题条目仍可能把列表序号写成格号；引用校验和图板布局截短检查值得继续接入自动链路。
4. 不要在原始仓库运行本轮修复或生成脚本；继续使用此分支与独立环境。
